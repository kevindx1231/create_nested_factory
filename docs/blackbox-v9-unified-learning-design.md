# 黑盒 v9 统一事件学习设计

## 目标与边界

黑盒学习把仍在真实 Pocket 空间运行的工厂观察为一份不可变生产合同。发布后，Pocket 空间及其嵌套空间被冻结并卸载，单方块运行器只按合同接收完整资源、结算应力和工具耐久、等待生产周期并提交完整产物。

现有双批次运行器、共享模拟输入输出面、超频、内部应力、蓝图、工厂迁移、航空学和嵌套冻结接口保持不变。计划格式升级为 v9，旧计划与旧蓝图不迁移。

## 状态流程

```text
CHUNK_LOADED
  └─ 前置检查通过
       └─ BLACKBOX_PREPARING（封口 1 tick）
            └─ BLACKBOX_LEARNING
                 ├─ 预热
                 ├─ 连续观察，至少完成三个统计分段
                 ├─ 尽早锁定普通加工路线
                 ├─ 按来源组持续收集事件和对应输出
                 └─ 全部来源达标 → 原子发布 → BLACKBOX_ACTIVE
```

玩家发起切换时先检查空间变更锁、内部无输入蓝图、玩家、传输参与者等既有限制。检查全部通过后立即删除旧计划和旧运行事务，再进入准备状态。学习失败返回 `CHUNK_LOADED`；学习期间已经真实发生的传输、库存和耐久变化不回滚，旧计划也不恢复。

学习会话不可持久化。服务器退出或区块实体重载会丢弃本次证据并回到常加载状态。

## 观察区间

预热结束后建立房间资源账本和来源证据集合。普通工厂的第一个观察分段从 100 tick 开始；没有产物时可延长到 200、400、800、1600 tick。检测到树木或作物候选来源后保持 100 tick 统计分段并持续观察，不再因为前三个分段没有凑齐来源证据而失败。

统计分段互不重叠，不清空或回滚真实工厂。每个分段记录：

- 完整物品身份的输入与输出；
- 完整流体身份的输入与输出；
- 外部应力、内部发电、峰值负载和总应力时间；
- 工具耐久消耗；
- 整个连续会话首尾的房间物品、流体和工具账本净额；
- 来源事件、来源额度和来源所在区间；

至少三个分段后，只要普通输入输出路线成立，就将该路线锁定。再生来源继续独立学习，最终与已锁定的普通路线合并；等待随机生长不会摊薄普通路线的效率。

房间首尾净额按边界角色归因。输入资源或未经边界的资源减少时补入成本，防止用预装库存补贴配方；只经输出边界的资源减少时从观测输出中扣除，不得变成配方输入。房间库存暂时增加不抵扣边界已支付的输入，也不额外增发未交付的产物。

从玩家请求切换开始计算统一绝对期限。默认 `6000` tick，配置接受任意大于 `1` 的整数。缺料、缺应力、输出堵塞和自然生长等待都计入时间。配置值在学习开始时快照，运行中修改只影响下一次学习。

## 来源适配器

主学习器只处理统一的来源证据，不包含圆石、玄武岩或树场分支。来源适配器负责：

- 扫描初始候选结构；
- 接收真实方块状态变化；
- 判断允许的动态结构状态；
- 记录完整来源事件及其观察区间；
- 记录边界产物并计算有限来源额度；
- 声明可归因产物、启动资本、自然等待和统计型产出；
- 提供版本化证明 ID。

圆石、玄武岩、树场和作物分别拥有验证次数配置，默认均为 `3`，范围为 `3..5`。树木按树苗种类分组，作物按注册 ID 分组；每组都必须取得足够事件，并在最新事件后观察到对应端口产物。同一 tick 内生成的 2×2 树只算一次事件。所有组达标并等待 40 tick 输出静默后才发布。

方块变化从 `LevelChunk#setBlockState` 的统一服务端入口通知。观察索引只登记正在学习的 Pocket 房间及其区块，因此普通世界和非学习房间不会扫描。适配器无法收到中间状态时，圆石和玄武岩可使用高速后备证明：候选结构有效、三个区间都有对应边界输出、不同 tick 的输出次数达到阈值，并且房间账本没有该资源的净减少。

所有预热后边界产物先进入未归因产物账本。来源稍后成立时可按额度认领；没有来源认领的部分进入加工路线，或在无外部投入且无合法来源时使学习失败。

## 路线归因

一份计划最多包含一条加工路线和一条再生路线：

- 外部输入及其可解释产物进入加工路线；
- 来源额度直接覆盖的产物进入再生路线；
- 同一资源身份同时来自两类路线时，来源额度覆盖的数量属于再生路线，剩余数量属于加工路线；
- 没有外部投入时，来源产物在房间内继续加工得到的最终产物可进入来源耦合的再生路线，但房间不能存在无法解释的库存耗损；
- 有外部投入且同一个来源适配器把输入和输出都识别为来源资源、又不能定量拆分时，拒绝发布；不同来源之间只按各自证据判断，避免圆石输入误伤独立树场等组合；
- 纯再生工厂出现无法由来源额度解释的物品、流体或工具耗损时，拒绝发布；普通或可明确归因的混合工厂把耗损计入加工成本。

## 速率与批次

普通加工路线用锁定前至少三个统计分段的总数量除以总秒数；再生路线用持续事件学习期间已认证的输出和总时间。对每项物品和流体分别执行近整数贴合：最近整数至少为 `1`，且差值不超过 `0.2` 时采用整数，否则保留观察得到的精确有理数。

编译器以三个区间的总时长为共同分母，把贴合后的速率还原为整数数量，并使用最大公约数约成最简整数资源向量和整数周期。运行器只交接完整物品和整数流体量；护目镜和蓝图以 `/s` 显示，最多两位小数并去掉末尾零。

应力合同沿用现有总 SU·tick、峰值外部应力、内部发电和峰值消耗语义。测试期间停机形成的零产出时间不会被删除，因此计划效率就是玩家测试条件下的实际平均效率。

## 原子发布与运行兼容

来源条件满足后依次完成房间净额检查、来源阈值检查、路线归因和计划完整性检查。全部通过后一次性构造 v9 `FactoryPlan`，再冻结完整嵌套树、销毁旧传输代次缓存并切换到 `BLACKBOX_ACTIVE`。任何步骤失败都不会留下部分计划。

黑盒与蓝图继续使用现有运行调度器。任意外壳输入面可提交能唯一归属的计划原料，任意输出面可提取共享输出；端口 ID 仍用于处理有歧义的输入。超频缩放周期与应力，内部发电抵扣外部需求，蓝图携带 v9 计划和必要启动资本。包含无输入蓝图的上级工厂仍拒绝学习。

## 日志与手动验收

INFO 日志记录开始、预热完成、每个观察区间、候选建立、来源归因、编译结果、发布及失败原因。逐物品、逐流体和逐方块事件只在 `blackboxDebugLogging` 开启时写 DEBUG，避免默认刷屏。

验收采用游戏内手动测试并核对 `latest.log`：普通物品、流体、工具耐久、圆石、玄武岩、树场、普通与再生混合、同身份拆分、内部来源继续加工、超频、内部应力不足与补足、蓝图复制、无输入蓝图嵌套拒绝、工厂破坏迁移和航空学移动。每项同时检查显示速率、实际长期吞吐、资源守恒、冻结状态及失败原因。

## 删除项

删除普通工厂第二轮独立验证、候选反复重置、树场隔离/等待/排出阶段、自然来源专用超时、普通学习停滞超时、主学习器中的来源种类判断、旧统计下界压低、旧每秒整数强制量化、学习阶段持久化、`room_edit_or_structure_interference`、玩家编辑失效标记和学习结构指纹。保留端口账本、连续会话房间快照、来源事件观察、传输托管和应力采集能力。

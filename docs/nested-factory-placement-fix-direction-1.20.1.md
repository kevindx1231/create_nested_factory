# Minecraft 1.20.1：嵌套工厂放置、入口资格与蓝图工厂修复方向

导出日期：2026-10-20。参考实现：Minecraft 1.21.1 项目当前 1.5.23 源码。

本文用于指导 1.20.1 同类问题的定位和修复，不是已经完成的 1.20.1 补丁。本次没有读取或修改 1.20.1 项目，也没有验证其构建、依赖版本或游戏内行为；下面的类名和方法名均为 1.21.1 参考位置，移植时需要先寻找目标项目中的对应实现。本文导出不修改现有源码、配置或构建产物。

## 1. 修复目标与已确认行为

核心规则：**同一父空间至多一个工厂取得本次放置的内部空间使用资格，但可以继续放置蓝图工厂，也可以放回保留旧空间绑定的工厂。空间绑定与入口资格必须分开。**

以普通有空间层级为例：

| 步骤 | 期望结果 |
| --- | --- |
| 首先放置普通 A | 创建空间 A，取得入口资格；护目镜不显示“该空间已有可进入的嵌套工厂” |
| 再放普通 B、C | 可以放下，不创建空间、不取得入口，只能应用蓝图；显示上述提示 |
| 拆除 A | 若 A 自己的内部仍有任意嵌套工厂则拒绝；允许拆除时掉落保留空间 A 绑定的工厂，立即释放入口资格 |
| A 拆除后观察 B、C | 保持原状态，不自动取得空间或入口 |
| 新放普通 D | 创建独立空间 D，取得入口资格；不能复用或覆盖空间 A |
| D 存在时放回绑定 A | 允许在原父空间合法位置放下；保留空间 A 绑定，但不可进入，只能应用蓝图并显示占位提示 |
| 再拆受限 A | 仍掉落保留空间 A 绑定的 A；不得掉成普通方块，不得释放 D 的入口资格 |
| D 被拆后观察已经放着的受限 A | 不自动升级、不抢占入口 |
| 入口空缺时，将 A 拆下重放 | 恢复原空间 A；不创建替代空间 |

补充约束：

- 无空间的蓝图工厂应用有效蓝图后，应正常执行物品、流体及已有兼容资源的生产边界，满足原计划的动力、工具、启动资本等要求。
- 无空间工厂拆除后结算为普通无绑定方块，不能携带蓝图、生产进度或真实资源副本。
- 受限绑定工厂取消蓝图后仍受限；旧空间继续停机，不能恢复原黑盒计划的执行或物理物流。
- 重启、区块卸载重载、祖先冻结和解冻均不能重新决定本次放置的入口资格。
- 普通挖掘、创造模式破坏、潜行扳手拆卸及显式销毁，需要核对其各自实际调用路径；不能只保护 GUI 销毁。

## 2. 先在 1.20.1 确认问题路径

按以下顺序寻找对应代码，不能只删除一条“已有子工厂”判断：

1. **物品放置入口**：是否因为父工厂已有子工厂，直接返回放置失败。
2. **方块实体初始化**：即使允许放下，是否仍因同层已有工厂而被分类为无效；是否清空旧空间编号或坐标。
3. **蓝图应用入口**：是否把“不可进入”等同于“不能应用蓝图”。
4. **生产与能力提供**：外壳物品、流体、包裹、扩展接口、可选模组能力及应力结算是否依赖真实内部房间。
5. **护目镜与进入提示**：客户端是否调用依赖服务端查询父工厂的进入判定；是否将所有不可进入原因都显示成同一个占位提示。
6. **破坏与掉落**：普通挖掘、创造模式、扳手、GUI、指令是否共用绑定保留和内部子工厂检查；是否走不同战利品路径。
7. **保存与恢复**：世界保存、物品绑定保存、目录快照、空间槽位注册是否区分“持有旧空间”与“当前可以使用旧空间”。

1.21.1 原问题的组合是：放置入口拒绝第二个方块，初始化把兄弟工厂分类为 `INVALID`，蓝图入口又拒绝非终端的不可进入工厂。护目镜还有独立问题：客户端父工厂查询得不到服务端，导致正常首个工厂也被显示为占位受限。目标版本是否完全相同，必须通过其实际代码确认。

## 3. 建议的状态划分

| 状态 | 持有独立空间绑定 | 本次放置有空间使用资格 | 可运行的生产 | 普通拆除 |
| --- | --- | --- | --- | --- |
| 正常空间工厂 | 是 | 是 | 原有常加载、学习、黑盒及蓝图流程 | 保存完整绑定和应持久化状态 |
| 同层无绑定蓝图工厂 | 否 | 否 | 仅应用的蓝图 | 结算后掉普通方块 |
| 同层受限绑定工厂 | 是 | 否 | 仅应用的蓝图，原空间停机 | 保存完整旧绑定 |
| 深度上限终端工厂 | 否 | 否 | 仅应用的蓝图 | 结算后掉普通方块 |
| 非法位置或绑定冲突 | 以原始数据为准 | 否 | 禁止执行 | 按异常绑定处理，不得擅自清空已有空间身份 |

参考实现使用 `siblingBlueprintOnly` 表示本次放置因同层入口占用而受限，使用 `terminalBlueprintOnly` 表示深度终端。前者既可能没有空间，也可能持有旧空间；因此不能单凭 `isBlueprintOnly()` 决定是否丢弃绑定。

建议集中提供少量语义明确的判定，目标版本可以使用不同命名：

- “是否持有真实空间绑定”：用于绑定掉落、目录、空间冻结范围、内部玩家和子工厂检查。
- “是否允许使用真实空间”：用于生成房间、常加载票、学习、空间物流和玩家进入。
- “是否仅允许蓝图”：覆盖同层受限与深度终端。
- “当前生产是否禁止”：集中处理祖先冻结、冲突、无效状态及尚未应用蓝图的受限工厂。

“没有空间 ID”应明确指不分配空间槽位、不注册可进入空间、不生成可搬运空间绑定。参考实现仍为每个方块生成内部 `FactoryId`，用于资源归属、目录和接口身份，且 `/cnf info` 会显示它；不能将所有无空间工厂的内部身份设为空或共用一个值。如目标要求连展示身份也隐藏，应单独处理展示层。

## 4. 放置与恢复的修改方向

### 4.1 普通未绑定方块

保留合法父空间、可建造位置和深度检查，移除“只因已有入口便拒绝方块放置”的限制。方块成功放置后统一分类：入口空缺时分配新空间并登记当前入口；入口被占用时成为无空间蓝图工厂。

无空间蓝图工厂不得覆盖父工厂的当前入口记录。相同游戏刻内的连续放置也必须有确定顺序，不能在放置检查和延迟初始化之间让两个方块都取得入口。

### 4.2 带旧绑定的物品

先检查原父工厂身份、合法位置、空间绑定有效性、物品是否过期及是否已被其他方块使用。原有防重复绑定、目录最新快照和房间变更锁校验需要保留。

- 入口空缺：恢复旧空间并取得资格，不重新分配槽位。
- 入口占用：保留原 `FactoryId`、空间槽位、空间坐标和可持久化配置，仅标记本次放置受限。
- 非法恢复：拒绝放置并保留物品；初始化异常路径也不能先将有效旧槽位置为 `-1` 或将旧坐标清零。

父空间只需要记录当前取得入口的工厂。其他受限绑定工厂保留各自空间所有权与目录记录，不需要扩展为多个同时可进入的入口。

### 4.3 卸载、重载与物品标记

将受限状态保存到世界 NBT，并同步客户端。重新放置物品可以重新决定资格，加载既有世界方块则必须恢复原分类。

物品中的“可搬运绑定”标记应在成功初始化后消费，不能原样长期保存在世界方块中，否则普通区块重载会再次执行放置分类。移除受限 A 时，只有当前入口记录的身份确实等于 A，才允许清理该记录，避免误删 D 的资格。

区块暂时未加载不等于入口方块已经拆除；不能因为运行时查询不到工厂就自动选举 B/C 接替。

## 5. 蓝图生产、冻结与能力

- 蓝图校验接受合法的受限蓝图工厂和终端，但仍拒绝无效位置、冲突绑定、不完整蓝图及已有生产事务等非法操作。
- 蓝图运行复用既有生产调度器、投入托管、产物交付和应力合同，不能新建一套“无需房间即免费产出”的旁路。
- 应用蓝图后提供外壳输入输出；空间端口与原房间物流仍关闭。不要让真实房间和虚拟蓝图同时生产。
- 对持有旧绑定的受限 A，保存原房间的冻结/停机状态，防止该区域被其他原因加载时恢复生产。仅释放自己申请的常加载票，不足以证明房间不会再执行。
- 无空间工厂参与父级逻辑冻结，但不能把零坐标当作真实房间加入空间冻结范围。
- 取消蓝图只恢复配置，不回滚已经提交的资源；受限绑定工厂不得解冻旧空间或重新获得入口。
- 缓存过的能力对象也要检查当前状态。取消蓝图、祖先冻结或方块移除后，仅让新的能力查询返回空值，不能阻止旧引用继续传输。
- 所有进入方式，包括直接交互、工厂通道和后代入口，都要使用服务端权威状态，避免绕过受限父工厂。

## 6. 破坏保护与掉落

将保护集中到一个可复用的查询中，并接入实际破坏入口。检查的是**被拆工厂自己的内部空间**，不是它所在的父空间；内部任意嵌套工厂都算，包括没有房间的蓝图工厂和终端。

内部子工厂检查不能只看“当前入口工厂”字段。可以按房间覆盖的区块遍历方块实体，筛选房间边界内的嵌套工厂，避免每次逐方块扫描整座房间；必须同时考虑未加载区块与索引失效。

掉落优先依据绑定归属：

```text
持有需要保留的空间绑定
    → 完整绑定工厂物品，包括当前入口受限的 A
没有空间绑定且属于合法蓝图工厂
    → 按既有规则结算真实资源，再掉普通工厂方块
```

核对以下细节：

- 不能将受限绑定 A 送入终端工厂的永久结算/身份删除分支。
- 普通搬运不等于显式销毁空间；绑定拆除不得回收旧空间槽位。
- 扳手可能自行调用战利品表再删除方块，绕过普通玩家破坏的绑定掉落。必须核实目标 Create 版本实际路径，确保只生成一份正确掉落。
- 投入、产物、流体、工具、电池及其他参与者按目标项目已有规则结算；不能既保留到绑定物品，又在世界里重复掉落。
- 除玩家破坏和扳手外，应另行核查爆炸、机器拆除等目标项目支持的路径是否符合预期；1.21.1 本次新增回归不等于这些额外路径已经全部验证。

## 7. 最大嵌套深度的边界

设有空间深度上限为 `N`，根工厂为深度 0。普通新方块的参考分类为：

| 自身深度 | 父空间入口空缺 | 父空间入口占用 |
| --- | --- | --- |
| 1 至 N | 有空间工厂 | 同层无空间蓝图工厂 |
| N+1 | 终端蓝图工厂 | 终端蓝图工厂 |
| 大于 N+1，或位置非法 | 无效/拒绝 | 无效/拒绝 |

需要区别：

- **自身深度为 N 的工厂**仍可拥有空间，完整适用 A→D→受限 A→重放恢复原空间的规则。
- **在深度 N 的内部空间继续放置的新方块**自身深度为 N+1，首个和后续方块全部是终端。它们不占用入口，均不创建空间，均只能运行蓝图，拆除均掉普通方块。
- 参考实现的终端不会显示“已有可进入工厂”的护目镜提示；尝试进入时使用“终端没有内部空间，只能运行蓝图”的提示。不能把终端误当成兄弟工厂占位。
- 终端虽然不能进入，但仍会阻止其所属的深度 N 空间工厂被拆除。
- 当前参考实现优先恢复有效旧绑定。如果降低配置前已有更深空间，其物品回到原父空间时不按新上限改为无空间终端；仍须满足原父空间和唯一绑定校验。

目标版本若没有“上限加一终端”机制，应先明确采用本节规则还是保留原限制，不要仅凭名称把“自身深度 N”和“放在深度 N 空间里”混为一谈。

## 8. 旧存档与版本移植注意点

### 8.1 旧存档迁移

- 新增状态字段缺失时，结合既有字段确认是否为旧版无空间无效方块。
- 仅对可核实父空间、位置合法且确实没有空间绑定的旧方块迁移；不要将错误父空间、重复绑定等异常一并合法化。
- 旧无空间方块迁移后仍为蓝图工厂，即使入口已经空缺，也不能趁迁移创建空间。
- 已有有效空间和终端分类应保留，不能因配置改变或新字段缺失重新分配空间。
- 缺失 NBT 数值键时，不应把默认读取到的 0 当成有效槽位；应验证键存在性及目标项目自己的无槽位约定。
- 如果持久化目录会用最新快照覆盖物品数据，必须让目录、物品与世界方块对新状态的含义一致，防止恢复时回放旧资格或旧生产状态。

### 8.2 1.20.1 适配

先核对加载器、Java、映射及 Create 依赖。移植的是状态和所有权语义，不是整段 1.21.1 API 调用：

- 1.21.1 参考代码使用物品数据组件和注册表查询参数；应通过 1.20.1 项目现有物品 NBT 与方块实体序列化方式实现同样的绑定保存。
- 能力提供、失效通知、流体接口、网络同步及事件类型按目标加载器和依赖实现适配，不能直接复制 NeoForge 包名。
- 核对目标 Create 的扳手回调、方块实体生命周期和物品/流体交互方式，保留其取消事件与资源结算语义。
- 若目标项目缺少目录、冻结管理或统一生产调度器，先找到其对应模块或最小必要接入点；不要把本修复扩展成无关系统重写。

## 10. 建议实施顺序与验收清单

1. 在目标项目建立能复现“第二个方块不能放/不能应用蓝图”的最小回归，记录当前失败。
2. 分离空间绑定、放置资格与运行模式；统一放置分类，先让后放方块成为合法蓝图目标。
3. 接通蓝图生产边界、旧空间停机及取消蓝图后的限制。
4. 修正持久化、物品标记消费、目录快照及旧存档迁移。
5. 接入拆除保护、绑定掉落和扳手路径，修正客户端提示。
6. 运行下面的交互场景，再执行目标项目已有构建与相关回归；记录实际命令、目标版本、依赖组合及结果。

| 验收场景 | 必须断言的结果 |
| --- | --- |
| 首放 A、再放 B/C | 仅 A 分配空间，B/C 可放置且可作为蓝图目标，提示准确 |
| 同一游戏刻连续放置 | 至多一个新工厂取得入口；放置失败不消耗物品或遗留槽位 |
| B/C 应用蓝图 | 真实投入后产生对应物品/流体输出，不能重复领取；动力不足时遵守原计划 |
| A 内放有空间子工厂或无空间蓝图方块 | 普通挖掘、创造模式、扳手和 GUI 的既定保护路径均拒绝拆除 A |
| 拆 A、放 D、放回 A | D 得到独立空间；A 保留原绑定但无法进入，可应用蓝图 |
| 受限 A 取消蓝图 | 原房间仍停机；原黑盒计划和缓存过的能力均不能绕过限制 |
| 再拆受限 A | 掉落保持 A 原身份/槽位/空间的绑定物品，不清除 D 的资格 |
| 拆 D、重放绑定 A | 恢复空间 A，不串房、不覆盖 D 空间；已放 B/C 不升级 |
| 重启与区块重载 | 受限状态、入口归属、原绑定和生产资源归属保持一致 |
| 父级切换黑盒/蓝图并恢复 | 蓝图后代随父级冻结/恢复；A 自己因入口受限的停机不被解除 |
| 重复/过期绑定物品 | 不覆盖现有入口，不复制空间或生产快照 |
| 旧无空间方块迁移且入口空缺 | 仍为无空间蓝图工厂，不新建房间 |
| 深度 N 的正常工厂 | A/D 搬运恢复规则仍成立 |

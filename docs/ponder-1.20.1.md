# 1.20.1 思索移植与手动验收

从 `D:\Program\create_nested_factory` 的 1.21.1 思索导出迁入，源项目只读。
目标环境沿用当前工程：Java 17、Create 6.0.8-291、Ponder 1.0.91、Forge/NeoForge 47。

## 实现

- 五类组件、八段思索、十个结构资源完整迁入。
- 保留原场景指令顺序、文字、坐标、等待时间、关键帧、实体动画以及自定义镜头代码。
- 客户端入口使用 Forge MOD 事件总线，并限定为客户端。
- 适配 ResourceLocation、NbtAccounter 和 ItemStack NBT 接口。
- 外部结构的物品堆转换为 1.20.1 的 `Count` 字节字段，并设置对应 DataVersion。
- 内嵌 SNBT 经 `PonderNbt` 递归转换后再交给实际方块实体/实体读取，保留无关 count 字段。
- 中英文各迁入 89 条思索翻译，保留原有其他翻译。
- 分类页标题沿用 1.21.1 的内容，通过 Ponder 自身的 LangBuilder 调用适配，避免生产环境的 Minecraft 方法混淆差异。
- 本模组的模型、材质、方块状态资源与源项目一致，无需替换。

## 可复现检查

```powershell
python tools/verify_ponder_port.py 'D:\Program\create_nested_factory'
.\build-1.20.1.ps1 clean build --offline
```

`testPonderPort` 使用 Minecraft 的真实 NBT 和物品堆读取器检查十个结构、59 段内嵌补丁、19 处物品堆，验证五类组件的八段场景绑定和中英文翻译。
完整构建还运行工程原有回归检查。

`migration/ponder-port/parity-report.json` 记录场景及资源一致性检查；`build.log` 记录完整构建。
源项目 `src` 下的文件通过迁移前 SHA-256 清单核对；备份及报告均位于 1.20.1 工程内。

如需重新导入更新后的导出，使用 `tools/port_ponder_1_20_1.py`，不要直接覆盖 1.20.1 的适配文件。
一致性验证中的源清单对应本次移植时的快照；源项目后续有意更新时需建立新的基准。

## 手动验收

将 `build/libs/create_nested_factory-1.20.1-1.5.23.jar` 替换到测试实例，保留完整 Create 及其依赖；不要安装 sources 或 test-only JAR。

在物品界面对以下物品按住 W 打开思索：

1. 嵌套工厂：依次播放进入与返回、物流运输、黑盒模式与搬迁、多层嵌套四段内容。
2. 嵌套端口：检查传送带上的金锭、金板及运输时序。
3. 嵌套扩展接口：检查漏斗、动力输入及红石禁用展示。
4. 嵌套应力端口：检查齿轮与转速表转动、正反转及转速切换。
5. 工厂通道：检查开关门、苦力怕实体进出及苦力怕头标记。

各段检查镜头移动、缩放、旋转，文字箭头及高亮是否对准目标；再检查暂停、关键帧跳转和重播。
切换中英文检查标题、正文和分类页标题。与 1.21.1 对照时使用相同窗口尺寸、GUI 缩放和资源包。

自动检查证明代码/数据的对应关系及构建结果；跨版本游戏内的画面与播放效果仍需此次手动验收。

# 无输入与混合工厂黑盒适配方案（设计稿）

> 本文记录 v4 方案及其来源认证背景，已由 [黑盒 v9 统一学习设计](./blackbox-v9-unified-learning-design.md) 取代，仅保留为历史背景。

本文基于当前工作区源码，并记录已落实的 v4 黑盒实现。目标是保留应力中继、端口物流、蓝图和不可直接访问的生产事务机制，同时让物料加工与可信再生共用一份计划模型。未注册的第三方再生来源仍需要提供 `RegenerativeSourceAdapter`，才可获得无物料生产权。

当前实现提供原版刷石、玄武岩和树苗—生长—回种状态的来源证据；完整周期整数配方、学习期峰值外部应力、完整流体成分身份、物品与流体有限库存对账、工具耐久成本、双路线事务、递归空间冻结，以及 v4 格式硬断代已经接入。树场默认验证 16 个完整周期；刷石和玄武岩默认验证 3 个。混合树场的掉落不能仅凭物品类型与加工产物区分，因此自动保持为耦合路线；第三方适配器只有提供事件级 `claimedOutputAmount` 才能安全拆出独立再生路线。

## 1. 当前实现与必须修改的约束

| 位置 | 当前行为 | 设计影响 |
| --- | --- | --- |
| BlackboxData.compileRecipe / hasCompleteRecipe | 无物品、流体输入时清空或拒绝配方 | 无输入配方必须通过独立的再生来源校验，而非简单放开空输入 |
| BlackboxData.buildIntegerRecipe | 全期统计后四舍五入为每 20 tick 整数 | 丢失低速产物，可能改变投入产出比，改为整数批量与有理数速率 |
| tickLearning | 200 tick 中前 100 tick 预热，后 100 tick 采样 | 不能覆盖树场完整再生周期，改为按完整事件和收敛条件结束 |
| tickDraining / setIgnoredOutputs | 等待库存总数稳定，扣除同种静态物品输出预算 | 无法证明库存原料加工、预置方块、流体和动态结构产物的来源 |
| calculatePortStressRequests | 按内部动力网络去重，扣除内部原生容量 | 复用去重规则，逐 tick 采集，保留每个网络的供需，不只存末帧 |
| enterActive / FactoryPowerProfile | 保存结束时功率档案 | 间歇负载末帧可能为零，必须保存完整周期负载和转速档案 |
| FactoryRuntime | 每条路线一个持久化事务，投入齐备、动力满足后交付 | 加工与再生独立阻塞，整厂只预留一份已学习应力 |
| scaledRecipe / ADR 0010 | 每项独立 floor，非零至少为 1 | 精确模式下需修改此约定，整份配方统一缩放，不能分别舍入 |

countItemsInFactorySpace 当前扫描索引内的 IItemHandler，并不构成覆盖流体、世界方块、掉落实体、运动结构和机器在制品的完整资源证明。现有旧配方也不能自动获得新的“可信再生”资格。

## 2. 正确性承诺

区分三件事：资源交易记账精确、已知配方比例精确、随机生产速度的统计估计。有限观察无法证明任意未知机器可以永久再生，也不能精确预测树木未来的随机生长和掉落。

因此采用“真实事件记账 + 再生来源适配器 + 依赖图编译”。对于没有适配器、无法解释物料来源的设备，继续真实运行并给出原因；不能以学习时间足够长作为授予无限生产的依据。

首批支持刷石、自然生长与机械收割树场、已能解释的加工机器及其组合。工具耐久、燃料、骨粉、流体、催化剂和环境条件均属于成本或运行前提。内部燃料库存不能被当成永久免费动力。

## 3. 配方与应力模型

一个工厂保存 `FactoryPlan`，其中包含加工与再生两类路线归属和共享资源/动力约束。路线包含：

- 外部物品、流体投入；内部中间品的真实来源；产物和副产物的整数向量。
- referenceTicks、referenceRPM、各动力网络的负载档案、最低工作转速。
- 外部 SU·tick 预算、最低有效运行时间，以及速度/环境限制。
- 再生来源证据、种苗/工具等保留量、结构版本、规则版本和完整计划指纹。
- 确定配方或统计配方标识；统计模式另存样本数、波动和置信区间。

通道类型：PROCESSING（外部物料加工）、REGENERATIVE（可信再生源）、COUPLED（再生源与加工依赖不能分开结算）。类型不能从“输入 map 是否为空”直接推断。

### 3.1 应力不是可随意储存的燃料

沿用 Create 应力负载语义，在有效转速下持续占用外部网络容量。SU·tick 是本模组的运行核算单位，不作为物理能量声称，也不引入可跨配方自由兑换的储能池。

每 tick 对每个内部网络记录消耗 Dg、原生供给 Gg、转速和过载状态：

    Uexternal(t) = Σg max(0, Dg(t) - Gg(t))
    Wexternal = Σt Uexternal(t)

不能先把所有网络的 D、G 相减：一个未连通网络的富余不能抵消另一个网络的缺口。同网络多个端口只计一次，父子工厂同一负载不能重复计费。供给必须可持续或对应明确燃料扣减。

完整周期还保存峰值和阶段顺序。可解释的周期重放阶段负载；随机/未能分段的负载使用完整可信样本及设备规则推导的保守负载预留。单纯使用平均 SU 会让原本带不动峰值负载的电源启动机器，不可采用。

第一版固定已验证的 RPM 档位运行。不同 RPM 重新校准，或由设备适配器提供已验证的速度规则。外部容量富余不会自动加速；断轴、零速、过载、条件失效时进度停止。周期等待时间计入吞吐模型，不能只测“锯断的几 tick”就省略树木生长时间。

### 3.2 精确数量

保存完整周期整数输入 I、输出 O 和时长 T，速率仅显示为 20I/T、20O/T。只有所有相关量可同时整除时才约分。不能分别四舍五入成每秒速率。

确定加工的投入产出比优先来自实际完成的配方事件；边界吞吐只负责测实际效率。采样结束时仍在机器中的在制品不得当作已完成投入。库存增减用于对账，不能把不同物品直接相减来推断加工配方。

随机源采用已知掉落/生长规则或明确标注的统计产率。统计产率可使用下置信界避免乐观估计，但不声称数学上的永久不超产。要求严格规则上界时，必须使用来源适配器提供的模型。随机状态持久化，不允许切模式、读档或重学反复重抽已提交的批次。

## 4. 学习状态机

    PRECHECK → WARMUP → BASELINE → CONTROLLED_RUNS → VERIFY → ACTIVE
                                                       ↘ NEEDS_MORE_DATA / UNSUPPORTED

1. PRECHECK：建立结构、端口、动力网络和可观测生产图。登记初始库存、流体、工具、实体、运动结构和再生状态。未覆盖的产物来源禁止编译。学习时限制人工改结构、放入物品等非计量干预；发生干预则作废当前样本。
2. WARMUP：处理真实积压，识别种苗和工作库存，不以固定总数稳定或超时作为正确性证明。预热产物正常交付，不计作学习新增产物。
3. BASELINE：阻断新的外部物料投入，在既有加工链排空后观察无输入分支。刷石需证明规则生成→破坏→再次生成；树场需证明种植→生长→收割→恢复可再生状态。采空预置矿石、锯掉现成树林不成立。
4. CONTROLLED_RUNS：分组供给计量输入，覆盖无供料、正常供料、缺一种料和受限供料。用于验证依赖、共享瓶颈及效率；不依赖简单“有料产量减无料产量”推导随机工厂配方。学习过程使用真实物流，不复制/回滚世界。
5. VERIFY：以未参与拟合的完整周期验证物料去向、回种储备、消耗品、应力档案和节拍。确定配方须严格匹配；随机产率显示误差并继续采样直至预设精度条件满足。达到时限但证据不足则延长或退出，不能强制成功。
6. ACTIVE：在结算边界停止真实生产，处理全部在途资源，再发布计划。学习期已经交付的产物绝不再次装入虚拟输出。中断学习后重启有效采样，不能用缺失账本继续编译。

精确记录仅在实际 EXECUTE 成功时计一次；simulate 不改变任何计数或状态。事务编号避免同一次传输在端口和外壳重复记录。物品继续使用 ItemVariant，流体也需要完整成分身份，不仅是 Fluid 注册 ID。

初始原料加工出的产物必须携带有限库存来源；例如箱中铁锭变成铁板，不能因铁板不在初始库存中而被认定为再生。来源追踪至少贯穿支持的加工事件、分流、汇流和动态结构；来源混合不明时拒绝编译。

## 5. 混合工厂的正确分解

### 独立并联

树场与铁锭压板分别形成通道。断铁锭时压板通道停机，树场仍可生产。两通道共享动力容量和物流容量，分配器对实际被批准运行的负载统一预留，不能给每个通道都分配整厂应力预算。

共同传动的固定机械开销按物理设备只记一次；同一设备的占用区间互斥。未知瓶颈采用已验证的整厂调度组合，不能把各分支单独测得的满速直接相加。

### 串联耦合

刷石→粉碎→洗涤要编译成内部有中间品约束的组合。内部石头每份只能用于导出或下一步加工之一；不能同时把全额石头与由这些石头得到的全额下游产物都列为外部收益。

如果外部也允许输入石头，则以两个真实来源共同供应同一个下游处理能力：

    处理量 <= 内部已生成中间品 + 已提交外部原料
    处理量 <= 下游设备在当前时间/动力下的处理上限

外部输入提高的是可用原料，不复制下游设备能力。中间品分配、出口分流和加工投入都必须守恒。

### 条件耦合

骨粉树场的自然生长与骨粉加速共享树位、收割装置，不能各自算一座完整树场。适配器可以提供经验证的两个互斥运行模式，缺骨粉时只运行自然模式；不支持可靠切分时整体作为耦合通道，拒绝猜测增益。

只有已证明独立的分支才拆开。物流连通性本身不能证明生产依赖，动力网络相同也不能证明必须同批运行。

## 6. 结算与防刷规则

`FactoryRuntime` 实现不可访问的事务语义。加工与再生路线各至多一个在途事务，不创建通用库存；相同产物在外部合并为一个稳定能力槽位，但内部所有权仍分离。

    WAITING_INPUT → RUNNING → OUTPUT_COMMITTED → DELIVERING → IDLE

无物料输入的可信再生通道可直接开始 RUNNING，但必须绑定计划、动力负载和环境条件。无输入进度也视为非空批次，避免现有 isEmpty 逻辑允许中途更换倍率/配方。

每 tick 顺序：验证计划与条件→分配共享设备/物料→原子预留外部应力→累积本批次有效时间/工作量→达到全部条件时一次提交产物。任何一项条件不满足均不兑现产物。剩余物品不能用于抵扣另一批应力。

- 输出堵塞：只保留已提交的有界剩余输出；对应通道停止新生产，不累积可在疏通后爆发的无限额度。
- 模拟调用：不推进时间，不扣输入，不减少输出，不修改随机状态。
- 切模式/拆除：完成前只能归还实际托管的未兑现投入；完成后只能交付剩余产物。已消耗的动力不退款，进度不物化为物品。共享中间品使用唯一所有权，不能多路退款。
- 存读档：计划指纹、批次 ID、阶段、投入、进度、剩余产物、随机状态作为同一权威状态持久化。正常重载恢复同一阶段，不二次提交；跨区块物流的异常崩溃一致性需事务日志及可协调端点，普通 NBT/setChanged 不能承诺任意断电 exactly-once。
- 真实/虚拟互斥：必须落实到房间 tick、方块计划更新、随机更新、实体、运动结构及可交互资源；仅移除强加载票不能证明停机。玩家进入或外部强加载时仍保证互斥，无法冻结的设备拒绝模拟。
- 结构变化：版本失效后停机，按照批次所有权处理资源，再重新学习。合法生长/收割属于适配器动态状态，不误判成结构篡改。
- 内部种苗、催化剂：固定启动资本必须被保留且不可重复提取。消耗性不足要表现为下一批缺料；蓝图不能复制可提取的资本库存。内建圆石与玄武岩来源中的水、岩浆、蓝冰和灵魂土不可从模拟合同提取，作为来源结构证明复用，不要求蓝图再次提交。
- 蓝图：复制计划、成本、条件和规则版本，不复制库存、进行中进度、余数或已提交输出；新目标从零开始。延续现有“保存源工厂成本”的语义，并新增可信再生校验。
- 嵌套：父级消费子级公开的计划/负载，不同时重放子级房间；同一资源和动力只结算一次。

## 7. 超频与时间限制

当前独立缩放各物品且最少为 1 的规则必须在新精确计划中替换。0.5 倍可用相同完整整数批次、双倍时间；整数倍可用完整批次倍数。非整数倍率用统一的有理数调度，不逐项舍入。

若保留“固定周期缩放数量”的界面约定，则采用跨周期整份配方累积，所有投入、产物、成本共用同一份额；不能只累积产物。此项需要同步更新 ADR 0010 的机制约定，本文不直接修改已接受文档。

机械超频不能自动缩短自然生长等等待约束。第一版只加速适配器声明可加速的机械阶段；若产品决定提供全厂魔法加速，应另设明确规则和匹配成本。普通外部 RPM、SU 富余和电池超频须分开显示。

## 8. 推荐模块与实施顺序

| 模块 | 责任 |
| --- | --- |
| FactoryLearningSession | 封装学习状态机、真实资源账本、样本校验；对外接收事件并返回学习状态/计划 |
| RegenerativeSourceAdapter | 刷石与树场两个实际适配器，解释再生周期、前提、消耗和可导出的产物 |
| FactoryPlan / FactoryPlanCompiler | 版本化计划、精确批量、路线归属和来源证据；显示速率不参与结算 |
| FactoryRuntime | 分别持久化加工与再生事务的投入、工具、进度和输出托管 |
| FactoryPowerProfile | 扩展为参考转速、按网络/阶段负载及外部需求档案 |
| PocketFreezeManager | 冻结/解冻整棵已加载嵌套树并管理后代持久化冻结标记 |

NestedFactoryBlockEntity 保留模式切换、能力交互、应力中继接入，避免继续把完整学习与调度算法叠入该类。

推荐先实施精确批量、完整学习证据和刷石单通道，再支持树场与随机模型，最后加入混合依赖图。每一步都必须让未支持结构维持真实模式；不能先放开空输入、以后再补防刷。

旧黑盒、旧运行时和旧蓝图完全不迁移。v4 计划指纹覆盖物品、流体、工具成本、时间、应力、来源证明、统计标记和路线归属；格式或指纹不匹配时不会解释为可运行生产权。

## 9. 验收场景

1. 刷石零物料输入能完成学习；断轴/过载不推进，恢复后无额外物品。
2. 树场跨多个完整周期学习；预置树、矿石、箱中原料和燃料耗尽不获得无限生产资格。
3. 例如每 200 tick 生产 1 件的低速配方保持产量；2→3 等比例在所有允许倍率下不变。
4. 同网络多个端口、独立多网络、父子工厂各自正确去重；单独富余网络不抵消另一网络缺口。
5. 独立树场与压板线断铁后仅压板线停；总负载不超过真实获批容量。
6. 内部刷石与外部石头共用粉碎机，产量不超过该设备能力，中间石头不重复导出。
7. 骨粉不足不保留骨粉加速产率；回种不足不继续无成本产木。
8. 输出堵塞、多次 simulate、切倍率、重新学习和蓝图复制不增加可领取总量。
9. 每个批次阶段存读档/正常重启/移动/拆除后，托管投入和剩余输出只有一个归属。
10. 玩家进入或相邻区块强加载时不存在真实与虚拟双重产出；未知设备显示不能验证的具体来源。

当前改动已通过主模组、Simulated 兼容模块和物流兼容模块的 Java 编译与完整 Gradle 构建。上述世界内场景仍需在 GameTest 或实际整合包中逐项验证，尤其是运动结构和第三方来源适配器。

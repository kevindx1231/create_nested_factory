# 黑盒 v5 重构实施方案

> 本文已由 [黑盒 v9 统一学习设计](./blackbox-v9-unified-learning-design.md) 取代，仅保留为历史背景。

本文是新版黑盒的统一实施依据。目标是在不加载真实 Pocket 房间及其嵌套后代的情况下，以单方块机器重放经过验证的物料、时间、工具和应力合同，同时支持普通加工、可信再生与混合工厂。

## 1. 不变量

1. 只有空间内机器真正取得的输入和真正交给端口的输出才进入学习记账；外部填入缓存本身不代表已经投入生产。
2. 每份虚拟产物必须由已托管投入或已认证再生来源、完整生产时间和生产应力合同共同授权。
3. 真实空间与黑盒运行互斥。根工厂进入黑盒或蓝图后，整棵嵌套树即使后来被其他加载器加载也不能运行。
4. 传输托管、生产事务、受托资本和房间库存是不同所有权，不使用一个通用“缓存为空”判断替代它们的生命周期。
5. 蓝图只复制计划、建议面布局和启动资本要求，不复制真实资源、运行进度、已提交输出或随机结果。
6. 已提交批次只能提交一次、退款一次或销毁一次。未提交的随机批次允许在读档后重新取得随机结果，这是经确认的资源防刷例外。

## 2. 模块边界

### FactoryTransit

取代 `FactoryPortChannels` 作为资源边界的唯一所有者，负责：

- 六个逻辑端口的物品、流体和扩展资源传输托管。
- INPUT/OUTPUT 方向、完整资源身份、学习代次和交付顺序。
- 物品即时返还信用；第一轮保留现有流体容量和调用行为，不新增吞吐上限。
- `beginTransition`、`seal`、`beginLearningGeneration`、`finalizeLearning`、`abortLearning`、`destroyAffectedTransit` 和完整序列化。
- 真实空间和学习期资源按逻辑端口托管；进入模拟模式时不把残留端口输入转换成生产投入。
- 类型化 `TransitParticipant` 注册，不再向兼容模组暴露可变 `CompoundTag`。

物品与流体是内建参与者。化学品等兼容资源必须实现封口、恢复、迁移、销毁和序列化；尚无计划语义的资源在正常空间模式保持原传输行为，在受控实验中一旦发生实际移动便使黑盒预检失败。热量等非库存条件在学习期保持可观察，由条件适配器决定是否能进入计划。

### FactoryLearningCoordinator

统一拥有封口准备和学习状态机，对外只接收所有权交接、结构修订、来源周期、房间参与者和应力事件。它控制输入闸门并输出进度、失败原因或候选计划，`NestedFactoryBlockEntity` 不再直接维护采样计数和库存启发式。

### RoomStateLedger

以稳定身份记录内部资本、工具和在制状态。普通资源使用方块位置、能力类型和逻辑槽位或储罐标识；传送带、掉落实体、运动结构及机器在制品使用类型化观察适配器。若同一资源视图无法稳定归一、参与者无法提供基线状态或资源去向无法解释，则相应路线不通过精确学习。

### FactoryPlan 与 FactoryRoute

`FactoryPlan` 保存版本、结构签名、启动资本合同、共享资源约束、生产应力合同和 `FactoryRoute` 集合。每条路线具有稳定 `routeId`，类型为 `PROCESSING`、`REGENERATIVE` 或 `COUPLED`，并保存：

- 按完整资源身份区分的投入与产出。
- 工具身份及每批耐久成本。
- 机械阶段、自然等待阶段和完成条件。
- 来源证明、随机规则、结构不变量和适配器规则版本。
- 应力阶段、参考转速、峰值 SU、SU·tick 及共享设备或互斥组声明。

总输出不再与“再生输出子集”重复保存。平均应力作为 `SU·tick / 周期` 的显示派生值，不作为独立持久化权威。

### FactoryRuntimeScheduler

以 `routeId → FactoryRuntime` 管理事务，并根据共享设备声明和整厂生产应力合同批准路线并发。只允许学习期间验证过的并发组合；无法证明独立的分支编译为一条耦合路线。

`FactoryRuntime` 保留生产所有权状态：

    ACTIVE_INPUT → RUNNING → OUTPUT_COMMITTED → DELIVERING
         ↑                                      │
         └──────── READY 原子提升 ───────────────┘

每条路线最多拥有一个活动输入批次和一个预备输入批次。活动产物完成托管后立即提升预备批次；输出堵塞时停止该路线，不累积可在疏通后一次释放的无限产量。

### FreezeLeaseRegistry

以稳定根工厂身份持久化冻结租约。后代工厂在加载和准备 tick 时沿父级身份检查租约；有效租约存在时不得强加载自身房间或运行真实生产。根退出模拟后释放租约，便携迁移和航空学移动转移根身份，孤儿租约由根身份一致性检查回收。

## 3. 状态机

    CHUNK_LOADED
        ↓ 请求学习
    BLACKBOX_PREPARING
        ↓ 下一服务器 tick 完成封口
    BLACKBOX_LEARNING
        WARMUP → BASELINE → CONTROLLED_RUNS → VERIFY
        ↓ 成功                              ↘ 失败/停滞
    BLACKBOX_ACTIVE                         CHUNK_LOADED

`BLACKBOX_DRAINING` 被删除。`BLACKBOX_PREPARING` 只持续到下一个服务器 tick，用于使旧能力实例失效、封存已有输入、建立学习代次并检查玩家与结构，不检查资源数量。

学习不使用固定总倒计时。每个实验保存最后一个有效事件时间；真实输入、生产、状态复位或来源周期事件才会刷新停滞期限。停滞后返回真实模式并报告具体原因，不用不完整数据编译计划。

学习期间服务器关闭或崩溃时放弃当前实验，合并传输代次并回到真实模式。准备或学习期间发生便携拆除或航空学移动时先执行同样的安全中止；已经激活的黑盒直接迁移计划、路线事务、托管资源和冻结根身份，并继续原批次。

## 4. 传输与端口语义

### 正常空间模式

保持现有外部能力、Create 主动物料传输和异步流体传输效果。模拟能力不设置每 tick、每个面或每个端口的传输配额，同一 tick 可以响应任意次数的插入和提取。输入容量为活动批次加一个预备批次；模拟输出容量为各路线两个输出交接单位，普通路线按完整批次、树场等流式路线按每秒结算单位计算。容量只提供所有权边界和背压，玩家外部物流决定实际传输速度。

### 学习代次

- 封口前的输入保留在旧代次并对空间隐藏，不要求消耗或替换。
- 无输入基线关闭新输入。
- 受控运行只开放指定逻辑端口、完整资源身份和计量额度。
- 输入在空间参与者实际取得时记录；输出在空间参与者交给端口时记录。
- 历史输出始终可被外部提取，但不进入当前学习统计。
- `simulate` 永不改变代次、信用、计量、事务或随机结果。

学习成功后，学习代次中尚未归属运行事务的输入与输出按硬切规则销毁。模拟模式只能接收激活后从共享 INPUT 面真实提交的新投入，学习残留不会成为隐藏的预付原料。

### 激活后的能力

黑盒和蓝图的外壳面只声明 INPUT、OUTPUT 或 NONE 访问权限，不进入计划指纹。所有 INPUT 面共享调度器需求视图，投入直接提交给缺少该资源的路线事务；同一资源可按稳定路线顺序拆分给多条路线。

所有已提交产物可从任意 OUTPUT 面提取。外部看到共享输出托管，各路线内部仍分别保存产物所有权和交付余量。

模拟模式可在任意生产阶段切换外壳面，修改只刷新该面的能力，不停止计划、不清空运行时，也不搬运资源。常加载、准备和学习模式仍按逻辑端口 ID 连接真实空间端口，改变其合同继续执行原有失效与销毁规则。

## 5. 精确学习

### WARMUP

封存切换前的输入缓存，让房间中已经开始的物理工作自然结束。该阶段的边界事件不进入候选计划。

### BASELINE

关闭新输入，通过 `RoomStateLedger` 记录资本、工具、在制状态、来源状态、结构修订和端口合同。无输入来源必须在此后完成适配器定义的生成、采集和复位周期；预置方块或库存不能仅因被输出而获得再生资格。

### CONTROLLED_RUNS

对观察到的输入签名依次执行无输入、单输入、完整输入、缺一输入和选定并发组合。每轮只开放规定投入，随后关闭该轮闸门，等待投入、产出、工具、资本和在制状态完成对账。实验数量超过配置上限、状态不能复位或来源不能归因时保持真实运行。

对刷石、玄武岩、树场等来源继续使用 `RegenerativeSourceAdapter`。动态区域由适配器声明允许状态和结构不变量，玩家或未知系统修改结构会改变结构修订号并使学习失败。完整结构签名只在开始和最终验证时计算，不在每 tick 扫描全房间。

### VERIFY

用未参与候选推导的独立周期重新执行路线和必要并发组合。物料向量、工具成本、阶段时间、应力合同、启动资本及结构不变量均通过后才发布当前格式计划。

随机输出只允许来自可信来源规则。每个尚未提交的周期在结算时重新取随机结果，不保存随机状态；已提交输出和批次提交标记正常持久化，因此同一已提交产物不能领取两次，但结算前读档可以改变随机结果。

### TREE_ROUTE

识别到原版树苗来源后，树场不受普通路线的最短 100 tick 采样截止控制。普通加工路线先用两段独立窗口验证并保存为尚未执行的候选；随后封存新的物料输入，等待房间内旧加工稳定，再开始树场专用窗口。真正黑盒只在所有路线完成后原子发布，学习期间不同时运行真实加工和虚拟加工。

树场窗口累计五次树苗实际长成原木的样本，并要求至少有对应树木产物经过输出边界。五次样本按整个树场累计，不要求每个种植位置各自完成五次；重新种植只负责让同一位置能够再次提供生长样本，不是样本成立条件。达到五次后继续记录短暂的输出传输收尾，再根据边界产物、房间资源减少、工具耐久和应力生成再生路线。树木、树叶、树苗和已认证生成位置在结构指纹中使用动态标记；未知方块仍参与结构指纹，真实玩家编辑仍立即终止学习。

混合计划持久化两份独立路线合同。加工路线和树场路线分别保存投入、产出、工具、周期、自然等待和应力，运行时按稳定路线 ID 分别结算。真实空间学习仍保留树木自然等待；树场完成来源证明并冻结为黑盒合同后不再执行随机刻，其完整虚拟周期可由烈焰电池缩放。整厂对外应力采用完整混合窗口与树场隔离窗口中的较大峰值，避免重复计算两条路线共同使用的设备。

## 6. 运行、应力与超频

加工路线必须先完整托管活动批次投入和所需工具，再进入运行；运行期间可以继续托管恰好一个预备批次。再生路线可以没有批次物料输入，但必须具有来源证明、完整时间和生产应力合同，并托管该来源实际声明的可消耗或可提取启动资本。内建圆石与玄武岩的固定环境块属于来源证明，不作为蓝图资本。生产应力可以由学习中验证的内部发电、外部应力或两者共同提供；内部发电量随计划持久化并参与指纹，不能由运行时当前快照临时补入。模拟输入从任意 INPUT 面直接提交到路线双批次所有权，不经过端口预付缓存。

调度器逐 tick 检查活动阶段的参考转速、峰值应力和共享设备约束。所有活动路线合计必须在计划验证过的并发包络内；一个网络或设备不能被多条路线分别按整厂容量重复使用。

烈焰电池和离散倍率继续使用现有交互。真实空间中的倍率只改变适配器声明可加速的机械阶段；冻结后的再生路线将经过验证的完整周期作为可缩放虚拟工作。整批物品、流体和工具向量不分别舍入。升降档都原子重定时所有路线：运行批次按完成比例换算进度，预备批次保留原料所有权，已取得的流式产物额度保持不变；应力和输入输出节奏在同一 tick 切换。

`FactoryPowerProfile` 只反映真实空间的即时发电与负载。黑盒、蓝图及其护目镜和运行调度从 `FactoryPlan.productionStressContract` 派生数据。常加载模式的护目镜和所有模式的 GUI 使用最近一秒真实边界传输遥测；该遥测只用于显示，不参与学习、配方或资源所有权。

## 7. 蓝图、破坏和迁移

- 蓝图复制当前格式计划、建议面布局、生产应力合同和启动资本合同，不复制 `FactoryTransit`、`FactoryRuntime`、进度或输出。
- 新蓝图工厂必须从外部一次性提交启动资本，相关路线随后才能运行。
- 退出黑盒或取消蓝图会恢复目标模式，并按硬切规则销毁尚未提取的模拟托管资源。
- 便携工厂物品保存计划、路线事务、全部传输托管、受托资本身份、超频状态和冻结根身份。
- 航空学移动使用相同持久化边界，不重建或退款活动批次。
- 显式端口合同或蓝图覆盖直接销毁受影响传输缓存；活动生产事务使覆盖操作失败。
- 不可迁移的最终破坏按现有产品规则处理：物品物化或销毁、流体和扩展资源明确销毁，并报告数量；任何路径都必须遍历全部传输参与者和路线事务。

## 8. 格式与失败策略

计划、路线运行时、传输托管、房间证据和蓝图升级为 v5。旧 v4 及更早格式不迁移、不猜测、不继续运行；发现格式不匹配时回到真实模式并执行明确的旧缓存销毁策略。新格式内的正常存读档必须恢复活动批次、已提交输出、信用余额和冻结租约。

重新学习时旧计划作为休眠计划保留。失败后只有结构签名、来源规则版本和端口合同仍完全相同，玩家才能手动重新启用；系统不自动恢复。

## 9. 删除和合并清单

以下现有机制应删除或由新模块取代：

- `OperationMode.BLACKBOX_DRAINING`、`tickDraining()` 及全部按缓存为空等待的状态判断。
- `initialInventory`、`initialFluidInventory`、`drainLastCount`、`drainStaticCount`、`drainStableTicks` 和对应 NBT/UI。
- 学习结束的 `portChannels.isEmpty()`、`learningSettleTicksRemaining` 和 `learningReadyTicks` 补丁链。
- `FactoryPlanCompiler.ignoredOutputBudget` 与 `ignoredFluidOutputBudget` 同身份扣减启发式。
- `FactoryPortChannels.clear()`、`clearFluidsAndExtensions()` 在配置或蓝图路径中的裸清空调用；统一改走参与者销毁事务。
- `extensionData(namespace)` 原始可变 NBT 接口；由类型化 `TransitParticipant` 取代。
- `FactoryPlan` 的总输出加再生输出子集双重表示，以及固定 `productionRuntime`、`regenerativeRuntime` 两实例。
- `FactoryPowerProfile` 只保存真实空间瞬时快照；模拟所需的内部发电、总消耗、外部缺口和 SU·tick 只由计划持久化。
- 全房间每 tick 来源发现和字符串结构指纹；改为运行索引、结构修订和适配器动态区域。
- 未使用的 `ignoredGameTime` 参数、与代码不符的流体过期注释、确认无调用者的通道辅助方法。
- 蓝图中始终为 `1.0` 且无独立来源的 `productionEfficiency`；界面效率由路线时间和生效倍率派生。

以下机制继续保留并接入新边界：

- `ItemVariant`、`FluidVariant` 的完整成分身份。
- `FactoryRuntime` 的投入、进度、工具和已提交输出所有权语义。
- 再生来源适配器及完整周期证明。
- 烈焰电池槽位、运行中原子倍率重定时，以及已验证再生路线的完整虚拟周期超频。
- 蓝图不复制真实资源、便携方块完整迁移状态、航空学移动钩子。

## 10. 实施顺序

1. 新建 `FactoryTransit` 和参与者接口，统一四个边界交接点，修复物品信用序列化；保持普通物流行为不变。
2. 用 `BLACKBOX_PREPARING` 和学习代次替换排空，先验证旧缓存永不阻止学习。
3. 实现 `RoomStateLedger`、阶段停滞和受控实验；物品、流体、工具及刷石来源先形成闭环。
4. 将计划改为路线集合，运行时改为按 `routeId` 管理，加入共享应力与设备调度。
5. 接入树场、随机规则、启动资本、逐阶段超频和混合路线验证。
6. 接入冻结租约、蓝图、便携迁移、航空学及扩展传输参与者。
7. 切换 v5 格式并删除本文件第 9 节列出的旧字段、方法、翻译和兼容分支。

每一步都以无法证明时保持真实模式为失败策略，不发布部分计划。

## 11. 验收场景

- 端口预存物品或大量流体时，封口准备在固定 tick 内进入学习，不等待缓存清空。
- 水和岩浆生成原石、动力钻头输出 2 原石/秒的工厂能形成“应力＋时间→原石”路线并持续输出。
- 铁锭压板与树场并联时，断铁锭只停止压板路线；树场继续运行，合计应力不超过验证合同。
- 刷石后继续粉碎和洗涤时，中间原石只能导出或加工一次。
- 同一原料只属于一条路线时可从任意 INPUT 面输入；属于多条路线时错误端口拒绝，正确端口正常接收。
- 已提交产物可从任意 OUTPUT 面领取，输出堵塞不会累计无限批次。
- 学习期间旧输入不参与无输入基线，历史输出可领取但不进入学习统计。
- 学习超时、服务器重启或学习期移动均安全回到真实模式，不产生负数计时或部分计划。
- 物品信用在存读档后保持原未偿数量，吞吐窗口不缩小。
- 配置语义变化销毁传输缓存并报告；生产事务非空时拒绝覆盖。
- 蓝图目标没有启动资本时不运行，提交真实资本后启动；复制蓝图不会复制资本或产物。
- 活动黑盒经便携迁移或航空学移动后继续原批次，不重复提交或退款。
- 根黑盒的未加载后代被外部加载时仍受冻结租约约束，不能真实运行。
- 随机批次提交后读档不能重复领取；提交前读档可以改变结果，符合 ADR-0023。

# ADR 0033：来源分组事件学习与房间净额计量

## 决策

黑盒学习继续使用一个连续会话。普通加工路线在至少三个统计分段后锁定；检测到再生来源时，真实 Pocket 空间继续运行，直到每个来源组都取得配置要求的完整事件和事件后的对应端口输出，或达到 `blackboxMaxLearningTicks`。

树木按树苗种类分组。同一树种在同一 tick 内生成的 2×2 树只算一次事件。作物按作物方块注册 ID 分组；成熟作物被收割或竖直作物新增一节时记录事件。混合农场必须让全部检测到的树木和作物组达标。最后一次已验证输出后保留 40 tick 静默期，让运输中的产物完成交接。

普通加工以端口边界统计为基础，只在整个连续会话结束时加入一次房间首尾有符号净额。输入资源或未经边界的隐藏资源减少时补入成本；只在输出边界出现的资源减少时，视为旧积压并从观测输出中扣除，不得转成配方输入。学习期内的库存增加不抵扣已支付输入，也不额外增发输出。每个方块位置只读取一个规范物品或流体能力，避免同一库存的方向包装对象被重复累计。没有外部输入且没有已验证再生来源时，房间预装库存不能单独建立永久配方。

`room_edit_or_structure_interference`、玩家编辑失效标记和学习窗口结构指纹检查全部移除。方块变化观察器仍保留，只用于收集来源事件。端口合同、无输入蓝图嵌套限制、启动资本、应力、工具耐久、冻结、运行事务、迁移和蓝图校验继续独立执行。

圆石、玄武岩等确定性来源使用生产凭证结算。每次合法的来源方块生成事件产生一个凭证，端口实际输出消耗同种物品的凭证；最终再生产量为生成凭证数与端口输出量的较小值。内部库存只承担时间缓冲作用，已被来源凭证覆盖的物品库存减少不会成为配方输入，未被凭证覆盖的历史缓存输出不会写入黑盒计划。内建确定性来源不再仅凭端口输出建立无输入计划。

流体混合可能用产物替换参与反应的流体，因此来源拓扑验证同时检查变化前方块所含流体和变化后的邻域。方块变化从实际区块状态提交处逐次分发，同一位置在同一 tick 内发生的多次合法生成分别计数。

Create 固定钻头存在独立的刷石优化路径：`DrillBlockEntity.optimiseCobbleGen` 验证流体交互后直接向传送带、漏斗或溜槽尝试插入掉落，真实来源方块保持不变。该方法返回成功时产生一个 Create 认证的来源凭证；是否真正形成学习产量仍由同种物品的端口实际输出量限制。普通固定钻头和移动结构钻头也上报完成事件，但事件本身不产生再生凭证，仍须观察到合法的真实方块生成。

删除旧的重复破坏推断及学习开始时的全房间圆石/玄武岩候选扫描。重复破坏只能证明钻头反复工作，不能证明中间方块没有由库存或其他输入补放；全房间扫描还会把预存建材误当成来源候选。来源候选现在只由真实合法生成或 Create 已验证的优化刷石事件建立。钻头事件通过正在学习房间的区块索引分发，不增加常加载模式和非工厂维度的逐 tick 扫描。

计划格式升级为 v9，不读取旧格式计划或蓝图。

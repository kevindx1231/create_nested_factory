# 以所有权交接事件取代黑盒全局排空

端口资源由统一的传输托管边界保存，学习输入只在空间内机器实际接收资源时记录，学习输出只在空间内机器实际交出资源时记录。模式切换使用短暂封口和学习代次隔离统计，不等待全部缓存清空，也不实施“新输入替换同类旧缓存”；物品与流体进入黑盒计划，其他资源必须通过类型化参与者提供封口、迁移、恢复和销毁语义，尚无计划语义时明确阻止黑盒激活。

这一决定取代 ADR-0001 的零缓存边界和 ADR-0007 的独立物品交接缓冲提案。它保留异步物流吞吐及真实在途资源，同时避免全局排空、同类替换账本和按初始库存身份扣减输出形成多套资源权威。

黑盒激活不以传输托管为空为前提。匹配计划的残留输入成为预付输入托管，不匹配输入保持隔离并在退出黑盒后恢复；历史输出先于新虚拟输出交付。第一轮重构不缩小现有流体缓存，以免改变极端吞吐和单次突发调用，自适应窗口另行决策。

旧排空模式由持续一个服务器 tick 的封口准备取代。该状态只负责终止旧能力交互、封存旧代次并建立学习代次，不按资源数量等待。

仅调整外壳物理面且保持逻辑端口 ID 和方向合同时，经过能力封口后保留计划与逻辑端口托管。改变逻辑端口 ID、方向或应用不同端口合同的蓝图会直接销毁受影响的传输托管并报告结果，不尝试迁移或匹配；存在未结束生产事务时拒绝执行。烈焰电池、受托工具和生产事务不属于传输缓存。该规则不适用于仅进入黑盒：模式切换仍按前述预付输入与历史输出规则保留真实资源。

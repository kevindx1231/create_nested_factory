# v1.5.22：冻结与性能模组兼容修复

日期：2026-10-18。范围仅为当前 Minecraft 1.21.1 / NeoForge 21.1.248 项目，版本保持 1.5.22。

## 变更

`LevelFreezeMixin` 从 `@Redirect` 改为 MixinExtras v2 `@WrapWithCondition`，优先级为 900。允许执行时保留第三方修改后的调用，冻结时跳过本次操作，删除原先手动 `ticker.tick()` 的逻辑。

这样可以避免与 Observable 5.4.4 的方块实体计时重定向争用调用点。既有 `ServerLevelRandomTickFreezeMixin` 保留 Lithium 的随机刻兼容；关键入口继续使用 Mixin 配置中的 `defaultRequire = 1`，不忽略冻结失效。

冻结修复没有更改房间冻结范围、冻结清单、计划刻与事件恢复、玩家规则或实体 tick 注入。v1.5.22 还包含来源学习调整和 Ponder 教程，完整发布范围见 [v1.5.22 更新日志](v1.5.22.md)；本记录只描述冻结兼容修复及其验证。

## 实际验证

在修复前，使用真实 Observable 5.4.4 和 Lithium 0.15.4 的独立 GameTest 运行重现了同样的 `@Redirect conflict` 和 `(0/1) succeeded`。原始复现日志：`build/freeze-compat-red-final.log`。

修复后四种独立 GameTest 组合均通过：

| 组合 | 结果 | 日志 |
| --- | --- | --- |
| 仅嵌套工厂及必要依赖 | 通过 | `build/freeze-compat-base.log` |
| 加 Lithium 0.15.4 | 通过 | `build/freeze-compat-lithium.log` |
| 加 Observable 5.4.4 | 通过 | `build/freeze-compat-observable.log` |
| Lithium 与 Observable 同时安装 | 通过 | `build/freeze-compat-both.log` |

测试执行真实的、经过 Mixin 转换的 `Level.tickBlockEntities()`，使用可计数 ticker 验证：

- 冻结房间内的方块实体没有执行 tick。
- 同区块不同高度的未冻结 ticker 继续执行；主世界 ticker 不受 Pocket 冻结影响。
- 解冻准备阶段保持冻结，完成解冻后恢复执行，次数与正常邻居一致。
- Observable 启用计时后，未冻结 ticker 的样本次数等于实际执行次数，冻结 ticker 没有执行样本，计时上下文正常清理。

Observable 的测试依赖固定为 Architectury 13.0.11 和 Kotlin for Forge 5.12.0。测试脚本按固定版本下载并校验文件摘要。

完整 Gradle `check build` 通过（33 个任务，19 个执行、14 个无需重新执行），日志为 `build/freeze-compat-check-build.log`。既有生产学习、冻结清单、移动通道、指令、物流和热量回归均通过。

## 重跑方式

项目根目录执行：

```powershell
.\scripts\test-freeze-compat.ps1
```

缓存完整时可使用 `-Offline`；指定单一组合时使用 `-Modes both`，其他可选值为 `base`、`lithium`、`observable`。

脚本调用 `:runGameTestServer -PfreezeCompat=<组合>`，跳过服务端不需要的客户端资产下载。每种组合使用 `build/freeze-compat/<组合>` 中的独立测试世界和 mods 目录，不修改现有 `run/` 环境。遇到测试目录中额外的模组时脚本报错，不自动删除文件。

测试类、测试模板和为 GameTest 提供 Pocket 维度的 flat 世界预设均位于 `src/freezeCompatTest/`，只有显式使用 `freezeCompat` 属性时才加入运行环境，不进入正式 JAR。

## 验证范围

本次集成验证覆盖服务端启动、方块实体冻结/解冻和 Observable 计时。未进行客户端界面手动验收，未新增随机刻、计划刻和方块事件的完整游戏内场景；既有冻结清单和恢复相关回归由完整 `check` 检查。

对于删除原版调用点、重写调度器或在其他线程执行机器的模组，仍需按实际版本专项适配。也不能解决两个其他模组之间独立存在的 Redirect 冲突。

# Create Nested Factory v1.5.2

Released October 12, 2026. This release includes the completed changes since v1.5.11.

## Factory commands and persistent directory

- Adds `/cnf info` to inspect the factory under the player's crosshair, including its name, UUID, dimension, position, mode, nesting depth, and available parent and descendant IDs. Inspection respects the player's server-side view and block interaction range.
- Adds `/cnf list root`, `/cnf list nested`, `/cnf mode <id>`, and `/cnf nested <id>` for registered rooms, factory modes, ancestor freeze state, and descendant rooms at every nesting depth.
- Adds UUID Tab completion and clickable IDs that suggest a mode query. Inspection requires no operator permission; all inspection commands except `info` also work from the server console.
- Adds a persistent directory that survives chunk unloading, portable-item transfers, and server restarts. Existing factories are indexed when their blocks or portable items become active after upgrading; directory queries do not force-load room chunks.

## Binding copies and space deletion

- Adds `/cnf copy <id>` for players with permission level 2. The item references the existing factory UUID and room; it does not allocate a second space.
- Prevents duplicate placement while the original remains placed, including when its chunk is unloaded. Restoring a binding copy uses the latest saved portable state, and destroying an unplaced command copy does not destroy the shared room.
- Adds `/cnf delete <id>` for permission level 2, including server-console callers. Deletion rejects rooms with descendants, players, or active room tasks; descendant checks include portable and roomless terminal factories.
- Cleans up placed or portable rooms incrementally and persists pending deletion across restarts. Root, nested, and legacy root slots become reusable only after cleanup completes.
- Permanently retires deleted UUIDs so old items and copies cannot rebind or affect a newly reused slot. Removes deleted rooms from saved freeze snapshots.

## Passages on moving structures

- Enables Factory Passage selection, markers, entry, and return when passages or their factories are on Simulated/Sable physical structures.
- Resolves travel in carrier-local coordinates and follows passage identity, current carrier pose, and velocity instead of stale world coordinates.
- Checks both world and carrier collisions before arrival. When the door center cannot fit the player, searches nearby supported positions in front of or behind the door.
- Keeps pending teleport destinations attached to the moving carrier until acknowledgement and preserves return sessions while a carrier is loading, migrating, or temporarily obstructed. Login recovery can wait for the factory carrier to become available.
- Releases passage re-entry protection after the player actually leaves the destination, preventing immediate return loops during moving arrivals.
- Requires both halves of a passage to move together during assembly and disassembly. Preserves endpoint identity and placement order, and prevents stale removal callbacks from unregistering a replacement endpoint.

## Interaction and visual fixes

- Sets the upper-front passage marker with a main-hand item and clears it with an empty main hand while not sneaking. Marker clicks do not toggle the door or consume the displayed item.
- Updates passage tooltips, status messages, and command messages in Simplified Chinese and English.
- Fixes the cyan-blue texture artifact at Nested Factory model position `[9,4,3]` by removing duplicate geometry with out-of-range UVs and updating Blockbench group indices.
- Rate-limits repeated arrival-failure diagnostics for the same player, passage, and failure state to once per 40 ticks; changed failure states are logged immediately when diagnostics are enabled.

## Documentation

- Updates the bilingual README for v1.5.2, including moving passages, marker interactions, the command reference, copy/delete behavior, and build verification tasks.
- Adds a detailed command guide and a changed-file summary.

## Compatibility and installation

- Minecraft 1.21.1, Java 21, NeoForge 21.1.x, and Create 6.0.9 or later within the 6.0.x series.
- Build dependencies: NeoForge 21.1.248 and Create 6.0.10-280.
- Moving-structure integration requires both Simulated 1.0+ and Sable 2.x. Optional compatibility remains bundled in the main JAR.
- Install `create_nested_factory-1.5.2.jar` on both client and server and remove the previous mod JAR from the instance.
- Existing-save directory entries are populated as factory blocks, inventory items, and dropped bound items become active. Old bound items in unloaded chunks or containers need to be loaded or taken out once before directory queries can find them.
